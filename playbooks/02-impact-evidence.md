# SOP 02｜成果证据库：把“我做过”变成可信的能力证明

<!-- EVIDENCE START -->

## 先看原始证据，再决定怎么做

**[EV12｜官方招聘实践](https://www.aboutamazon.com/news/workplace/amazon-leadership-principles-interview)** 亚马逊官方招聘指导要求申请者结合领导力原则提供以客户、主人翁意识和长期结果为中心的具体经历，并解释自己做过什么。

**因此可以做：**准备六张STAR-L案例卡，标明团队贡献和结果的核实方式。 **但不能推断：**不能认为所有公司按亚马逊面试，也不能直接套用其页面示例数字当本人经历。

**[EV05｜335个独立样本](https://pubmed.ncbi.nlm.nih.gov/28749153/)** Lacerenza等发表于2017年的元分析整合335个独立样本，领导力培训在学习、迁移和结果等指标上总体有正向效应，效果随设计方式不同而变化。

**因此可以做：**用真实项目练一个能力，安排30天复盘，检查结果是否迁移到工作。 **但不能推断：**培训改善管理学习/绩效指标不等于能够预测高管升职；各研究设计和场景有差异。

> 提醒：这些来源包括企业披露、平台观察数据、实务综述和研究样本；相关性不是因果。下方动作由本项目设计，不是研究保证的晋升步骤。详情见 [完整证据图谱](../evidence/RESEARCH_ATLAS.md)。

“负责1000万收入”“增长50%”“管过30人”这些句子没有上下文，价值很有限，也可能构成误导。高管候选人的证据应当可以解释**实际职责、结果、限制和取舍**。

## 1. 一个案例必须含七个字段

1. 背景：问题是什么？是谁决定解决？
2. 基线：起始指标与统计口径；没有数字就写实际业务状态。
3. 角色：你是A（拍板人）、R（执行负责人）、C（咨询对象）还是I（知情人）？
4. 动作：由你亲自决定或推动的关键选择。
5. 结果：结果时间窗、结果证据、业务方是否认可。
6. 归因：外部周期、投放资源、其他团队是否贡献很大？
7. 反思：失败、成本、复用条件与下一次会怎么做。

## 2. 手把手改写一个案例（纯虚构示例）

原句：*“主导用户增长，新增用户增长50%。”*

更可信的示例：*“参与某产品为期8周的拉新项目，负责落地页测试与反馈汇总；同期新增注册从每周200到260。期间投放预算同步增加，因此无法仅凭前后变化断定测试贡献了全部增长。通过渠道拆分后，向团队建议继续测试有效渠道。”*

这里的200和260只是展示口径的**虚构教学数字**，禁止作为个人真实经历使用。

## 3. 非增长岗位一样需要成果

财务：关账及时性、差错率、审计问题整改。人力：关键岗位到岗周期、离职风险、培训的业务迁移。产品/技术：交付可靠性、客户问题解决、质量、成本。客服与运营：投诉闭环、客户体验、过程稳定性。指标不能独立构成业绩，必须标出可控因素与副作用。

## 4. 五分钟对抗质询

“这是你的决定吗？”“没做这个项目会怎样？”“换了统计口径还成立吗？”“是否损害了质量或团队健康？”“有什么证据证明你理解失败原因？”每个问题都答不上来，则把该案例从晋升材料中暂时降级为“参与经验”。

**失败分支**：拿不到公司保密数据，不得复制原始业务报表；只能在获准范围内使用摘要、个人可合法持有的考核评价或公开作品。
