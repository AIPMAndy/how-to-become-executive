# 第三阶段｜没人向你汇报，怎么先练负责人能力？

<!-- EVIDENCE START -->

## 先看原始证据，再决定怎么做

**[EV06｜180个团队](https://rework.withgoogle.com/intl/en/guides/understand-team-effectiveness)** Google Project Aristotle分析180个团队（115个工程项目组和65个销售组），识别与团队有效性相关的五个动态因素：心理安全、可靠性、结构清晰、意义与影响。

**因此可以做：**在项目章程加入决策权、依赖、责任人、升级与复盘节奏。 **但不能推断：**相关研究，不证明照抄Google会议方式就必然提升KPI；也不等于群体成员素质不重要。

**[EV04｜近300人 / 12类挑战](https://www.ccl.org/articles/leading-effectively-articles/first-time-managers-must-conquer-these-challenges/)** CCL分析近300名参加初任经理领导力项目的新兴领导者，归纳12项挑战，包括管理昔日同事、授权、绩效反馈、冲突和跨组织沟通。

**因此可以做：**制定新经理30天清单：明确目标、1对1、授权边界、反馈与冲突升级。 **但不能推断：**不能据此证明12项挑战有统一排序，或每名经理都经历全部挑战。

> 提醒：这些来源包括企业披露、平台观察数据、实务综述和研究样本；相关性不是因果。下方动作由本项目设计，不是研究保证的晋升步骤。详情见 [完整证据图谱](../evidence/RESEARCH_ATLAS.md)。

<!-- EVIDENCE END -->


你还不是经理，也可以先争取一个跨部门项目Owner。关键在于**有清楚的结果、授权和最后的验收人**。只负责开会、催进度，不能算真正负责业务。

## 3.1 把授权确认清楚

用[项目授权一页纸](../templates/project-charter.md)写：要解决什么问题、结果怎么衡量、什么事情你能决定、什么事情必须请示、需要哪个部门支持、什么时候停止、谁批准资源。

直属主管不愿授权？先争取一个四周可回滚的小试点，不要一开口就索要整个业务控制权。

## 3.2 RACI和利益相关者

例如你在做产品上线：产品、研发、运营、风控都参与；却未必每个人都知道谁是最终拍板人。用[RACI](../templates/raci.csv)标清执行责任与最终责任，避免“人人都负责=没人负责”。

对有依赖的同级部门，一开始就说明对方需要付出的成本、能获得的价值，以及如果资源冲突怎么升级。不要靠“老板让你配合我”来做协作。

## 3.3 每周只有三个必须回答的问题

1. 本周与目标相比发生了什么事实？
2. 还有哪些风险、依赖或取舍必须决定？
3. 谁在何时交付下一步行动？

如果会议没有决策，就减少会议。把关键决定记录到[决策备忘录](../templates/decision-memo.md)。

## 3.4 别把上线当完成

产品上线、活动结束或系统部署之后，还需要有人接手运维、处理投诉和复盘。没有后续负责人和监控，项目价值可能只是一次演示。

**完成：**书面授权、角色图、四周决策日志、阶段验收、交接复盘。
