参与共建

贡献前先守住4条边界

  1. 所有案例可核实：如果是想象的情境，明确写“假设”。真实案例请获得适当授权并去标识化。
  2. 不要上传企业机密：包括客户名单、价格条款、内部财务预算、组织架构、人员评价、会议纪要、未公开战略和源码。
  3. 方法有条件：请说明适用角色、公司规模和不能照搬的例外，不做“一定晋升”保证。
  4. 明确出处：引用研究、法规或公开第三方工具时标明公开链接及核验日期，不大段复制有版权内容。

新增任务

在 data/guide.json 对应阶段增加任务，包含 id、title、action、proof、blocked、sources。完成标准必须能留下可以验证但不泄露隐私的证据。

运行：

python3 build.py
python3 -m unittest discover -s tests -v
node tests/calc.test.js

贡献方式

请优先提交：跨团队项目的权责边界、可匿名复用的一页业务模板、面试反例、管理者反馈话术、行业岗位责任差异、错误链接。提交PR说明原文与变化、必要的截图（仅公共网页或自制素材）、可能的误用场景。

v2 投稿质量门槛

  • 提交真实案例需有合法披露权限，且去掉客户、员工、公司未公开业务信息；无法核验的金额与收益一律标记为假设。
  • 新的行动卡需写出：具体动作、完成证据、操作步骤（至少3步）、无授权时的替代方法、失败处理和高风险边界。
  • 研究主张需链接来源，标明研究对象和不可外推之处；不得把相关性包装成因果关系。
  • 不允许提供操弄绩效、歧视、泄露商业秘密或规避公司治理责任的技巧。
  • 更新 data/guide.json 后执行 python3 build.py，同时提交生成的 HTML 阅读页面，并运行 python3 -m unittest discover -s tests -v 和 node tests/math.test.js。
